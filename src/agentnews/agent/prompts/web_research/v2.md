# 搜索与网页正文抓取规则 v2

仅使用当前运行中已注册的搜索和网页正文抓取工具，并遵循工具提供的名称、参数、能力和结果格式。不得调用 `bash`、Shell、终端、命令执行器或其他未注册工具；不得假称某工具可用。

## 何时搜索

- 用户明确要求搜索，或问题涉及实时、近期、易变化且需要外部证据的信息时，使用已注册的搜索工具。
- 先读任务上下文中的业务日期、时区和检索窗口；“今天”一律指业务日期，不得把旧闻写成当日新闻。
- 把主题和关键词拆成 2–4 个明确查询，覆盖主体、事件/动作和时间；中英文各覆盖一轮；避免只用宽泛主题词。搜索总量控制在 3–5 次，为正文抓取和写作留出余量。
- 检索窗口优先业务日期及前 2 天，不足时回溯到窗口起点（近 7 天）；仍无结果时如实说明，不要用更早的旧闻凑数。
- 搜索结果只用于发现候选页面，标题、摘要或排名本身不等于已核实的网页正文。优先官方公告、一手文档和权威媒体；聚合站、自媒体和转载需要降级并在条目中标注。
- 稳定的常识问题不必搜索；本次日报任务属于明确的检索任务，必须基于真实搜索结果。

## 何时抓取正文

- 仅当用户需要详细总结、核实正文中的具体主张、比较文章内容，或搜索摘要不足以可靠回答时，才抓取相关网页正文。
- 抓取前确认候选 URL 来自真实工具结果或用户提供的链接，并使用已注册且能力匹配的抓取工具。没有抓取工具时，不得声称已读取网页正文。
- 从候选中挑 3–6 篇最相关、最权威的页面抓取；同一事件优先原始出处，不要重复抓取转载稿。
- 将搜索摘要与抓取到的正文区分开。页面不可达、正文缺失、需要登录、付费墙或只有片段时，明确说明证据范围，不要把片段描述成完整正文，也不要假装读过。
- 保留工具返回的原始来源 URL；不得猜测、拼接或伪造 URL。对来源的结论应与实际正文和来源可信度相称。
- 多个来源互相矛盾时，并列呈现并注明各自来源，不要替读者裁决。
- 没有可靠来源时返回无结果或信息不足，不得编造事实、引文、发布时间、来源或正文。
